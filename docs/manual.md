# TicketingOS — Εγχειρίδιο χρήσης

Τελευταία ενημέρωση: 11 Νοεμβρίου 2026

## 1. Εισαγωγή και βασικές έννοιες

Το TicketingOS είναι ένα helpdesk: οι πελάτες ανοίγουν αιτήματα (tickets), η ομάδα υποστήριξης τα απαντά και τα λύνει, και η διοίκηση βλέπει απόδοση, χρόνο και χρεώσεις. Λειτουργεί από browser και ως εφαρμογή στο κινητό (PWA), στη διεύθυνση της εγκατάστασης, π.χ. https://support.softify.gr.

| Έννοια | Τι σημαίνει | Παράδειγμα |
| --- | --- | --- |
| Workspace (tenant) | Ένας ξεχωριστός «χώρος» με δικούς του χρήστες, tickets και ρυθμίσεις. Τα workspaces δεν βλέπουν το ένα το άλλο. | Softify |
| Organization | Μια εταιρεία-πελάτης μέσα στο workspace. Ένας χρήστης μπορεί να ανήκει σε πολλές. | «Acme ΑΕ», με domain acme.gr |
| Ρόλος | Τι μπορεί να κάνει κάθε άτομο: Customer, Agent, Admin, Super Admin, ή ένας ρόλος που φτιάχνετε εσείς. | Ο «Junior agent» απαντά αλλά δεν συγχωνεύει tickets |
| Ticket | Ένα αίτημα με θέμα, περιγραφή, μηνύματα, αρχεία και ιστορικό. Έχει αύξοντα αριθμό. | #128 «Δεν τυπώνει ο εκτυπωτής» |
| Status | Η φάση του ticket. Ορίζονται ελεύθερα· κάποια μετρούν ως «κλειστά». | Open → Pending → Resolved → Closed |
| Priority | Πόσο επείγει. Καθορίζει την προθεσμία (SLA). | Low, Medium, High, Urgent |
| SLA | Ο χρόνος μέσα στον οποίο πρέπει να λυθεί ένα ticket ανάλογα με την προτεραιότητα ή το συμβόλαιο του πελάτη. | Urgent = 4 ώρες |
| Internal note | Σημείωση μέσα στο ticket που βλέπει μόνο το προσωπικό. | «Ο πελάτης έχει παλιό firmware» |
| Group | Ομάδα agents που αναλαμβάνει μια κατηγορία tickets. | Billing, Technical |

Πώς διαβάζεται: οι ενότητες 3–6 είναι εγχειρίδια ανά ρόλο, βήμα-βήμα. Οι ενότητες 7–16 περιγράφουν κάθε λειτουργία αναλυτικά, με παραδείγματα. Η 17 αφορά την εγκατάσταση και η 18 τα συχνά προβλήματα. Τα ονόματα κουμπιών και μενού γράφονται όπως εμφανίζονται στην εφαρμογή (στα αγγλικά), π.χ. **Settings → Integrations**.

## 2. Ρόλοι και δικαιώματα

Τέσσερις βασικοί ρόλοι, από τον λιγότερο στον περισσότερο ισχυρό. Ο Agent είναι προσαρμόσιμος: ο Admin ανοίγει ή κλείνει κάθε δικαίωμα και μπορεί να φτιάξει δικούς του ρόλους (custom roles).

| Ρόλος | Ποιος είναι | Τι βλέπει | Τι κάνει |
| --- | --- | --- | --- |
| Customer | Ο πελάτης | Τα δικά του tickets, όσα συμμετέχει στην ομάδα (team) και, αν είναι manager, όλα του organization του | Ανοίγει και απαντά σε tickets, ανεβάζει αρχεία, βαθμολογεί την εξυπηρέτηση, διαβάζει το Help Center |
| Agent | Το προσωπικό υποστήριξης | Ανάλογα με τα δικαιώματα: όλα τα tickets ή μόνο τα δικά του, της ομάδας του και τα ανατέθητα | Απαντά, γράφει σημειώσεις, αλλάζει status/priority, καταγράφει χρόνο, απαντά στο chat, χρησιμοποιεί το AI |
| Admin | Ο διαχειριστής του workspace | Όλα του workspace | Όλες οι ρυθμίσεις, χρήστες, ρόλοι, συμβόλαια, αντίγραφα |
| Super Admin | Ο ιδιοκτήτης της εγκατάστασης | Όλα τα workspaces | Branding (όνομα/logo), είσοδος ως οποιοσδήποτε χρήστης, όρια στους Admin |

### Δικαιώματα που μπορεί να έχει ένας Agent

Τα δικαιώματα αλλάζουν στο **Settings → Roles & permissions**. Ο Admin έχει αυτόματα όλα.

| Ομάδα | Δικαίωμα (όπως φαίνεται) | Τι επιτρέπει |

| Ticket access | Internal notes | Εσωτερικές σημειώσεις |
| Ticket access | Answer live chat | Απαντήσεις στο chat του site |
| Ticket access | AI assistant | Το μενού AI δίπλα στο Send reply |
| Ticket details | Change status / priority / category | Αλλαγή των αντίστοιχων πεδίων |
| Ticket details | Edit custom fields | Προσαρμοσμένα πεδία (π.χ. αρ. παραγγελίας) |
| Ticket details | Assign to others / Move between groups | Ανάθεση σε άλλους και αλλαγή ομάδας |
| Ticket details | Tag tickets / Manage followers | Tags και μέλη ομάδας του ticket |
| Ticket details | Log time | Καταγραφή χρόνου |
| Ticket details | Delete files | Διαγραφή αρχείων άλλων |
| Ticket details | Use macros | Έτοιμες ενέργειες με ένα κλικ |
| Bulk & data | Bulk edit / Merge / Link / Export to CSV | Μαζικές αλλαγές, συγχώνευση, σύνδεση, εξαγωγή |
| Bulk & data | Share saved views | Κοινόχρηστες προβολές |
| Bulk & data | Manage everyone’s time | Χρόνος άλλων και αναφορά χρεώσεων |
| Knowledge base | Write / Publish / Delete articles | Άρθρα Help Center |
| Reports | View reports / Schedule report emails | Αναφορές και προγραμματισμένα emails |

Έτοιμα πρότυπα ρόλων για γρήγορη αρχή: **Read-only**, **Junior agent**, **Team lead**, **Content editor**. Τα δικαιώματα Administration (Roles & permissions, Security rules, Manage administrators) υπάρχουν μόνο στον Admin και δεν δίνονται ποτέ σε Agent.

## 3. Εγχειρίδιο Πελάτη (Customer)

Ο πελάτης ανοίγει αιτήματα, συνομιλεί με την ομάδα και βλέπει την πρόοδο — από το web, το κινητό ή το chat του site.

### 3.1 Πρώτη σύνδεση

1. Ανοίγεις το link που ήρθε με email (πρόσκληση ή «ορισμός κωδικού») και ορίζεις κωδικό.
2. Συνδέεσαι με email και κωδικό. Αν ξέχασες τον κωδικό: **Forgot password**.
3. Στο κινητό: μενού του browser → **Προσθήκη στην αρχική οθόνη** ή το κουμπί **Install app**, για να το έχεις σαν εφαρμογή.

### 3.2 Νέο αίτημα

1. Πατάς **New ticket**.
2. Γράφεις **θέμα** (μια σύντομη φράση) και **περιγραφή** — τι γίνεται, τι δοκίμασες, τι βλέπεις.
3. Διαλέγεις **κατηγορία** και **προτεραιότητα**, αν ζητούνται.
4. Σέρνεις εικόνες ή αρχεία στο πλαίσιο, ή κάνεις επικόλληση μιας οθόνης (Ctrl+V).
5. Η εφαρμογή σου προτείνει άρθρα του Help Center που ίσως λύνουν ήδη το θέμα.
6. Πατάς **Create ticket**. Παίρνεις email επιβεβαίωσης με τον αριθμό.

**Παράδειγμα καλού αιτήματος:** Θέμα «Δεν τυπώνει ο εκτυπωτής του λογιστηρίου». Περιγραφή: «Από σήμερα στις 9:00 ο HP LaserJet στο λογιστήριο δείχνει offline. Έκανα επανεκκίνηση, δεν βοήθησε. Επισυνάπτω φωτογραφία του μηνύματος.»

### 3.3 Παρακολούθηση και απάντηση

- Στο **Tickets** βλέπεις τα αιτήματά σου με την κατάστασή τους. Με αυτό το φίλτρο **Overdue** βλέπεις όσα καθυστερούν.
- Μέσα στο ticket γράφεις στο πλαίσιο απάντησης και πατάς **Send reply**. Το κείμενο σώζεται αυτόματα ως πρόχειρο («Draft saved»), οπότε δεν χάνεται αν κλείσει η σελίδα.
- Αν απαντήσεις σε κλεισμένο ticket, ξανανοίγει αυτόματα.
- Μέσα σε 15 λεπτά μπορείς να **διορθώσεις** ή να **διαγράψεις** ένα μήνυμά σου από το μενού ⋯ δίπλα του.
- Από το μενού ⋯ μπορείς επίσης να κάνεις **Quote in reply** (παράθεση).
- Εικόνες και PDF ανοίγουν μέσα στη σελίδα με ένα κλικ.
- **Print / PDF**: εκτυπώνεις ή αποθηκεύεις όλη τη συνομιλία.

### 3.4 Ομάδα και συνάδελφοι

- Στην κάρτα **Team** προσθέτεις συναδέλφους από το ίδιο organization ως viewer (βλέπει) ή collaborator (βλέπει και απαντά).
- Στην κάρτα **CC by email** βάζεις διευθύνσεις που θα παίρνουν αντίγραφο των δημόσιων απαντήσεων.
- Αν είσαι **manager** του organization, βλέπεις όλα τα tickets της εταιρείας σου.

### 3.5 Βαθμολογία και ειδοποιήσεις

- Όταν λυθεί το ticket, βλέπεις 5 φατσούλες (και email) για να βαθμολογήσεις την εξυπηρέτηση. Μπορείς να αλλάξεις την απάντησή σου αργότερα.
- Στη σελίδα **Notifications** διαλέγεις τι θέλεις να σου έρχεται (in-app, push, email), ώρες ησυχίας και σύνοψη ανά ώρα ή ημέρα.
- Το 🔔 στην κορυφή ενεργοποιεί ειδοποιήσεις push στη συσκευή.

### 3.6 Χωρίς λογαριασμό

Στο site της εταιρείας το κουμπί **Help** ανοίγει το **chat**: γράφεις όνομα, email και μήνυμα και μιλάς με έναν agent. Αν δεν απαντήσει κανείς σε λίγα λεπτά, ανοίγει ticket και η απάντηση έρχεται με email. Εναλλακτικά: **Send a request** για τη φόρμα υποστήριξης.

## 4. Εγχειρίδιο Agent

Ο agent ξεκινά από την ουρά του, απαντά, καταγράφει χρόνο και κλείνει. Τι βλέπει και τι μπορεί να αλλάξει εξαρτάται από τον ρόλο του (ενότητα 2).

### 4.1 Η μέρα ενός agent

1. **Dashboard**: ανοιχτά, επείγοντα και εκπρόθεσμα tickets με μια ματιά.
2. **Views** στο μενού (π.χ. «Τα επείγοντά μου»): κάθε προβολή δείχνει πόσα tickets έχει τώρα.
3. **Live chat** (αν έχεις το δικαίωμα): ο αριθμός δίπλα δείχνει πόσοι επισκέπτες περιμένουν.
4. Ανοίγεις το ticket, διαβάζεις το **Customer history** στο πλάι (πόσα tickets έχει ο πελάτης, βαθμολογία, συμβόλαιο).
5. Πατάς **Assign to me**, απαντάς, γράφεις χρόνο και πατάς **Mark resolved** όταν τελειώσει.

### 4.2 Απάντηση και εσωτερική σημείωση

- Γράφεις στον editor (έντονα, λίστες, πίνακες, εικόνες, κώδικας). Με **@** αναφέρεις συνάδελφο, π.χ. «@Μαρία δες το».
- Τικάρεις **Internal note** για σημείωση που δεν βλέπει ο πελάτης (το πλαίσιο γίνεται κίτρινο).
- **Canned reply** (εικονίδιο μηνύματος με +): έτοιμη απάντηση με τα στοιχεία του ticket. Παράδειγμα: «Γεια σας {customer.first\_name}, ελέγξαμε το {ticket.number}…» γίνεται «Γεια σας Γιάννη, ελέγξαμε το #128…».
- **Βιβλίο** στον editor: ψάχνεις άρθρο του Help Center και μπαίνει link.
- **Υπογραφή**: μπαίνει αυτόματα στις δημόσιες απαντήσεις (τη γράφεις στη σελίδα Notifications → Reply signature).
- **Time spent** δίπλα στην απάντηση: γράφεις π.χ. 0:15 και καταγράφεται χρόνος μαζί με την απάντηση.
- **Αρχεία**: σέρνεις οτιδήποτε πάνω στην απάντηση. Με «Files visible to staff only» ένα log δεν το βλέπει ο πελάτης.

### 4.3 Ιδιότητες του ticket (πλάι)

- **Properties**: status, priority, ένας ή περισσότεροι assignees, κατηγορία, group. Κάθε αλλαγή σώζεται αμέσως και γράφεται στο History.
- **Files**: όλα τα αρχεία με φίλτρο, λήψη, διαγραφή και **All (ZIP)**.
- **Time**: χρονόμετρο και καταχωρίσεις (ενότητα 11).
- **Requester**: στοιχεία πελάτη, organization και υπόλοιπο συμβολαίου (π.χ. «8h 30m left of 10h»).
- **Team**, **CC by email**, **Sub-tickets**, **Linked tickets**, **Tags**.

### 4.4 Μηνύματα

Από το ⋯ κάθε μηνύματος: **Quote in reply**, **Copy link**, **Pin to top** (το μήνυμα εμφανίζεται πάνω από τη συνομιλία), και για 15 λεπτά **Edit** / **Delete**. Το προσωπικό βλέπει τις παλιές εκδόσεις (History).

### 4.5 Live chat

1. Ανοίγεις **Live chat**. Οι συνομιλίες με πορτοκαλί κουκίδα περιμένουν απάντηση. Ακούγεται ήχος σε νέο μήνυμα.
2. Πατάς τη συνομιλία και γράφεις (Enter = αποστολή, Shift+Enter = νέα γραμμή). Η πρώτη απάντηση σε κάνει υπεύθυνο της συνομιλίας.
3. **To ticket**: αν το θέμα θέλει συνέχεια, γίνεται ticket με όλη τη συνομιλία. **End**: κλείνει και αποθηκεύεται ως ticket.

### 4.6 AI βοηθός (αν είναι ενεργός)

Το κουμπί **AI** δίπλα στο Send reply: Suggest a reply, Summarize the ticket, More professional / Friendlier / More empathetic / Shorter / Fix spelling, Translate. Το κείμενο μπαίνει στο πλαίσιο για έλεγχο, με **Undo**. Τίποτα δεν στέλνεται μόνο του (ενότητα 13).

### 4.7 Χρήσιμες συντομεύσεις

| Θέλω να… | Κάνω |
| --- | --- |
| βρω ένα ticket γρήγορα | Αναζήτηση στην κορυφή: αριθμός (#128), λέξη, ή assignee:me |
| δω αυτά που είναι ανατεθειμένα σε μένα | Φίλτρο **My tickets** |
| δώσω ένα ticket σε συνάδελφο | Properties → Assignees |
| εφαρμόσω μια συνηθισμένη συνταγή | **Macros** → απάντηση + αλλαγή status με ένα κλικ |
| ενώσω διπλό ticket | **Merge into…** και γράφω τον αριθμό του άλλου |
| στείλω το ticket σε συνάδελφο | **Share link** ή ⋯ → Copy link σε μήνυμα |
| δουλέψω στο κινητό | Εγκατάσταση ως εφαρμογή και push ειδοποιήσεις από το 🔔 |

## 5. Εγχειρίδιο Admin

Ο Admin στήνει και συντηρεί το workspace από το **Settings**. Η σειρά παρακάτω είναι η προτεινόμενη για ένα νέο workspace.

### 5.1 Πρώτη ρύθμιση βήμα-βήμα

1. **General**: όνομα workspace, κατηγορίες (π.χ. Account, Billing, Technical), το κάτω μενού του κινητού και τα **Attachments** (μέγιστο μέγεθος, πλήθος και τύποι αρχείων).
2. **Workflow**: statuses (ποια μετράνε ως «κλειστά»), priorities με χρώματα, και SLA σε ώρες ανά priority (π.χ. Urgent 4h, High 8h, Medium 24h, Low 72h).
3. **Users**: προσκαλείς agents και πελάτες. Αν δεν έχει ρυθμιστεί email, εμφανίζεται link για να το στείλεις εσύ.
4. **Roles & permissions**: προσαρμόζεις τον ρόλο Agent ή φτιάχνεις νέους (βλέπε ενότητα 2).
5. **Groups**: ομάδες agents, αυτόματη ανάθεση (εκ περιτροπής ή στον λιγότερο φορτωμένο) και δρομολόγηση ανά κατηγορία.
6. **Organizations**: εταιρείες-πελάτες με email domain (νέοι χρήστες με @acme.gr μπαίνουν αυτόματα), managers, **τιμή ανά ώρα** και **συμβόλαια** (ενότητα 11).
7. **Notifications & email**: SMTP ή Microsoft 365 για τα emails, ποιος παίρνει τι (ενότητα 10).
8. **Ticket fields & CSAT**: προσαρμοσμένα πεδία (π.χ. «Αρ. παραγγελίας», «Συσκευή») και έρευνα ικανοποίησης.
9. **Tags & replies**: tags, canned replies, macros, ticket templates.
10. **Automations**: κανόνες (ενότητα 14).
11. **Integrations**: φόρμα και widget, live chat, API keys, webhooks (Slack/Teams/Viber), AI.
12. **Backups & data**: ημερήσια αντίγραφα, εξαγωγές, GDPR (ενότητα 16).

### 5.2 Χρήστες

- **Πρόσκληση**: όνομα, email, ρόλος και organization(s). Ο χρήστης παίρνει email για να ορίσει κωδικό.
- **Deactivate**: κλείνει την πρόσβαση χωρίς να σβήνει τίποτα. **Remove**: διαγραφή λογαριασμού με τα tickets του.
- **Reset password**: στέλνει link νέου κωδικού.
- Ένας agent μπορεί να ανήκει σε πολλά organizations: τότε βλέπει όλα τα tickets τους και εμφανίζεται πρώτος στην ανάθεση.

### 5.3 Παράδειγμα: νέος πελάτης με συμβόλαιο

1. Settings → Organizations → **New organization**: «Αλφα Λογιστική», domain alfa-logistiki.gr.
2. Ανοίγεις το organization → **Hourly rate** 45 → Save rate.
3. **New contract**: «Silver 2027», 01/01/2027–31/12/2027, 20 ώρες, Reply within 4h, Solve within 24h.
4. Προσθέτεις τον υπεύθυνο τους ως **Manager** και έναν agent σας στο organization.
5. Αποτέλεσμα: τα tickets τους έχουν προθεσμία 24 ωρών, το ticket δείχνει υπόλοιπο ωρών και στο τέλος του μήνα βγαίνει χρέωση από το Reports → Time & billing.

### 5.4 Έλεγχος

- **Audit log**: κάθε αλλαγή ρυθμίσεων, σύνδεση, εξαγωγή και διαγραφή, με ώρα και IP. Εξάγεται σε CSV.
- **Security**: ελάχιστο μήκος κωδικού και κανόνας «γράμματα και αριθμοί».
- **Settings → Notifications**: πότε έτρεξε τελευταία φορά το cron και το ιστορικό αποστολών.

## 6. Εγχειρίδιο Super Admin

Ο Super Admin είναι ο ιδιοκτήτης της εγκατάστασης: βλέπει όλα τα workspaces και έχει όλα τα δικαιώματα. Δημιουργείται με την εντολή `php bin/make-super-admin.php email` στον server.

- **Πλατφόρμα** (μενού χρήστη): λίστα όλων των workspaces και χρηστών τους. Με **Enter** μπαίνεις σε ένα workspace και με **Exit** βγαίνεις.
- **Make this my workspace**: ορίζεις το «σπίτι» σου (π.χ. Softify), ώστε να δουλεύεις και ως agent: παίρνεις tickets, εμφανίζεσαι στους assignees και μπορείς να ανήκεις σε organizations.
- **Sign in as** (στους χρήστες): βλέπεις την εφαρμογή όπως ένας συγκεκριμένος χρήστης, για έλεγχο προβλημάτων. Μια μπάρα στην κορυφή σου θυμίζει ότι είσαι «ως άλλος», και καταγράφεται στο audit log.
- **Branding** (Settings → Platform → Branding): όνομα εφαρμογής και logo. Το logo εμφανίζεται στο μενού, στη σύνδεση, στα emails και στις εκτυπώσεις· χωρίς logo χρησιμοποιείται το προεπιλεγμένο (ακουστικά με check). Εδώ ενεργοποιείς ή κλείνεις και το «Create a workspace» στην αρχική.
- **Δικαιώματα Admin** (Settings → Roles & permissions → Administrator): ανά workspace κλείνεις συγκεκριμένα δικαιώματα των Admin, π.χ. χωρίς Manage administrators ή χωρίς Erase personal data.

**Παράδειγμα:** πελάτης λέει «δεν βλέπω το ticket του συναδέλφου μου». Κάνεις **Sign in as** τον πελάτη, βλέπεις ότι δεν είναι manager του organization, βγαίνεις με **Exit** και τον κάνεις Manager στο Settings → Organizations.

## 7. Tickets αναλυτικά

Κάθε ticket περνά από τα ίδια βήματα: δημιουργία, δρομολόγηση, συνομιλία, λύση, βαθμολογία.

1. **Δημιουργία**: web, email, φόρμα/widget, live chat ή API.
2. **Δρομολόγηση**: κανόνες, AI triage, ανάθεση σε agent ή ομάδα, SLA.
3. **Συνομιλία**: απαντήσεις, εσωτερικές σημειώσεις, αρχεία, χρόνος.
4. **Λύση**: status Resolved και ειδοποίηση στον πελάτη.
5. **Βαθμολογία**: ο πελάτης αξιολογεί την εξυπηρέτηση (CSAT).

Αν ο πελάτης απαντήσει σε λυμένο ticket, ξανανοίγει και επιστρέφει στη συνομιλία.

### 7.1 Από πού έρχονται

| Κανάλι | Πώς |
| --- | --- |
| Web | Ο πελάτης πατά New ticket |
| Από το προσωπικό | Ο agent ανοίγει ticket για έναν πελάτη και δηλώνει κανάλι: Phone, Email, In person, Chat |
| Φόρμα υποστήριξης | /support/το-workspace σας, χωρίς λογαριασμό |
| Live chat | Αναπάντητο ή ολοκληρωμένο chat γίνεται ticket |
| REST API | Από άλλο σύστημα με API key |

### 7.2 Νέο ticket από το προσωπικό

- **For a customer**: αναζήτηση πελάτη ή δημιουργία νέου με email.
- **Start from a template**: έτοιμα θέματα με συμπληρωμένα πεδία (π.χ. «Νέος υπάλληλος — λογαριασμοί»).
- **Similar tickets**: όσο γράφεις το θέμα, βλέπεις παρόμοια και αποφεύγεις διπλό.
- Επιλογές agent: ανάθεση, group, CC, δική σου προθεσμία, sub-tickets.
- Τα κομμάτια της φόρμας ανοίγουν ή κλείνουν από Settings → Tags & replies → New-ticket form.

### 7.3 Προθεσμίες (SLA)

Η προθεσμία υπολογίζεται με αυτή τη σειρά: (1) ημερομηνία που έβαλε ο agent, (2) «Solve within» του συμβολαίου του πελάτη, (3) SLA της priority. Παράδειγμα: ticket High στις 10:00 με SLA 8h → προθεσμία 18:00. Αν ο πελάτης έχει συμβόλαιο «Solve within 4h» → 14:00. Το ticket δείχνει «Due in 2h» ή «Overdue by 4 days».

### 7.4 Η σελίδα του ticket

- **Conversation** / **History**: μηνύματα χωριστά από τις αλλαγές (ποιος άλλαξε τι και πότε).
- **Pinned**: τα καρφιτσωμένα μηνύματα πάνω από τη συνομιλία.
- **Ανίχνευση σύγκρουσης**: βλέπεις αν άλλος agent διαβάζει ή γράφει ταυτόχρονα.
- **Γρήγορες ενέργειες** πάνω: Macros, Assign to me, Mark resolved, Link ticket, Merge into…, Share link, Print / PDF, Article from ticket.
- **Merge**: το διπλό κλείνει και όλα του (μηνύματα, αρχεία, άνθρωποι) μεταφέρονται στο άλλο. **Link**: σχετικά tickets χωρίς συγχώνευση.
- **Sub-tickets**: μικρότερες εργασίες μέσα σε ένα μεγάλο ticket, με δικό τους assignee.

### 7.5 Αρχεία

- Εικόνες φαίνονται ως μικρογραφίες· εικόνες και PDF ανοίγουν στον viewer (βελάκια ή swipe για επόμενο).
- Πριν την αποστολή ελέγχεται μέγεθος και τύπος· ένα .exe απορρίπτεται με μήνυμα.
- Κάρτα **Files**: όλα τα αρχεία του ticket με φίλτρο (Images / Documents / Other) και λήψη όλων σε ZIP.
- Διαγραφή: τα δικά σου μέσα σε 15 λεπτά, αλλιώς χρειάζεται το δικαίωμα Delete files. Κάθε διαγραφή φαίνεται στο History και στο audit log.

### 7.6 Εκτύπωση

**Print / PDF** ανοίγει καθαρή σελίδα με στοιχεία, συνομιλία και λίστα αρχείων. Το προσωπικό μπορεί να συμπεριλάβει και τις εσωτερικές σημειώσεις. Από το παράθυρο εκτύπωσης επιλέγεις «Αποθήκευση ως PDF».

## 8. Λίστα, Board και προβολές

Τα tickets φαίνονται ως **List** ή ως **Board** (κουμπιά πάνω δεξιά). Τα φίλτρα ισχύουν και στα δύο.

### 8.1 Φίλτρα και αναζήτηση

- Φίλτρα: status, priority, κατηγορία, tag, assignee, group, organization, και τα γρήγορα **My tickets**, **Unassigned**, **Overdue**.
- Αναζήτηση: λέξεις από θέμα και μηνύματα, αριθμός (#128), email πελάτη, ή με τελεστές όπως `assignee:me` ή `assignee:"Μαρία"`.
- Ταξινόμηση: νεότερα, παλαιότερα, πρόσφατη αλλαγή, προτεραιότητα, προθεσμία, αριθμός.
- Η ένδειξη **Frustrated** / **Angry** δίπλα στο θέμα (μόνο για το προσωπικό) δείχνει δύσαρεστο πελάτη, αν είναι ενεργή η αυτόματη ταξινόμηση AI.

### 8.2 Board

- Κάθε στήλη είναι ένα status με το δικό του χρώμα (χρωματιστό φόντο, γραμμή πάνω και στις κάρτες).
- Στον υπολογιστή σέρνεις μια κάρτα σε άλλη στήλη για να αλλάξει status.
- Στο κινητό οι στήλες είναι η μία κάτω από την άλλη. Τα κουμπιά των status πάνω σε πάνε στην ενότητα. Για αλλαγή status ανοίγεις το ticket.

### 8.3 Αποθηκευμένες και κοινόχρηστες προβολές

1. Βάζεις φίλτρα, π.χ. status Open + priority Urgent + group Technical.
2. **Save view** → όνομα «Επείγοντα Technical».
3. Η προβολή εμφανίζεται στο μενού **Views** με ζωντανό μετρητή.
4. Με το δικαίωμα Share saved views πατάς το εικονίδιο share: η προβολή φαίνεται σε όλη την ομάδα (εικονίδιο ανθρώπων). Κάθε άτομο βλέπει μετρητή με τα δικά του δικαιώματα.

### 8.4 Μαζική επεξεργασία και εξαγωγή

- Τικάρεις πολλά tickets στη λίστα και αλλάζεις status, priority, assignee ή tags μαζί.
- **Export**: τα φιλτραρισμένα tickets σε CSV για Excel.

## 9. Live chat, φόρμα και widget στο site

Ένα μικρό κομμάτι κώδικα στο site σας βάζει ένα κουμπί **Help** κάτω δεξιά. Αν το live chat είναι ενεργό, ανοίγει chat· αλλιώς τη φόρμα υποστήριξης.

### 9.1 Ρύθμιση (Admin)

1. Settings → Integrations → **Support form & website widget**: ενεργοποίηση, τίτλος, χρώμα, αν ζητείται κατηγορία.
2. Αντιγράφεις τον κώδικα του widget και τον βάζεις πριν το `</body>` του site.
3. Settings → Integrations → **Live chat**: Turn on, τίτλος, χαιρετισμός, και σε πόσα λεπτά γίνεται ticket αν δεν απαντήσει κανείς (προεπιλογή 5).
4. Στους agents που θα απαντούν δίνεις το δικαίωμα **Answer live chat**.

### 9.2 Τι γίνεται σε ένα chat

| Στιγμή | Επισκέπτης | Agent |
| --- | --- | --- |
| Έναρξη | Γράφει όνομα, email, μήνυμα | Ειδοποίηση, μετρητής στο μενού, ήχος |
| Πρώτη απάντηση | Βλέπει «Μαρία joined the chat» | Γίνεται υπεύθυνος της συνομιλίας |
| Κανείς δεν απάντησε (π.χ. 5ʹ) | «Ανοίξαμε το ticket #131, θα απαντήσουμε με email» | Υπάρχει ticket, μπορεί να συνεχίσει στο chat |
| **To ticket** | Ενημέρωση με αριθμό ticket | Η συνομιλία γίνεται ticket, ανατεθειμένο σε αυτόν |
| **End** ή 30ʹ χωρίς μηνύματα | «Η συνομιλία έληξε», κουμπί νέου chat | Αποθηκεύεται ως ticket (κλειστό αν απαντήθηκε) |

### 9.3 Φόρμα υποστήριξης

- Διεύθυνση: /support/το-slug-σας (π.χ. https://support.softify.gr/support/softify). Δεν χρειάζεται λογαριασμός.
- Ο νέος αποστολέας γίνεται πελάτης (και μπαίνει στο organization του ανάλογα με το domain του email) και παίρνει link για να παρακολουθεί το ticket.
- Ενώ γράφει, του προτείνονται άρθρα του Help Center.
- Προστασία από spam: κρυφό πεδίο, έλεγχος χρόνου συμπλήρωσης και όριο αιτημάτων.

## 10. Ειδοποιήσεις

Κάθε γεγονός στέλνει ειδοποίηση σε τρία κανάλια: **in-app** (🔔 στην εφαρμογή), **push** (στο κινητό/υπολογιστή) και **email**. Ποιος παίρνει τι ορίζεται στο Settings → Notifications & email.

### 10.1 Γεγονότα

| Γεγονός | Ποιος το παίρνει συνήθως |
| --- | --- |
| New ticket | Το προσωπικό |
| Request received | Ο πελάτης (επιβεβαίωση με αριθμό) |
| Reply | Ο πελάτης, οι assignees, η ομάδα του ticket |
| @mention | Αυτός που αναφέρθηκε |
| Assigned | Ο νέος assignee |
| Status changed | Ο πελάτης και η ομάδα |
| Added to a ticket | Αυτός που προστέθηκε στην ομάδα |
| SLA approaching / SLA missed | Assignees και admins |
| Still unassigned | Το προσωπικό |
| Reminder to customer | Ο πελάτης, όταν περιμένουμε απάντησή του |
| Closed automatically | Ο πελάτης (με έρευνα ικανοποίησης) |

### 10.2 Ρυθμίσεις workspace (Admin)

- **Πίνακας ανά ρόλο**: για Customers / Agents / Admins, κάθε γεγονός × κανάλι. Κάθε κουτάκι είναι προεπιλογή που αλλάζει ο καθένας, ή **locked** (κλειδαριά) ώστε να μην αλλάζει.
- **Χρόνοι κανόνων**: πόσα λεπτά πριν την προθεσμία ειδοποίηση, πότε «still unassigned», υπενθύμιση στον πελάτη μετά Ν ημέρες, αυτόματο κλείσιμο μετά Ν ημέρες.
- **Κείμενα email**: θέμα και μήνυμα κάθε γεγονότος με μεταβλητές όπως {ticket.number}, {actor.name}, {workspace}.
- **Delivery log**: λίστα αποστολών με τον λόγο κάθε αποτυχίας, **Resend / Retry all failed**, **Send test to me**.
- Στο τέλος της σελίδας: **Email notifications** με τις ρυθμίσεις SMTP ή Microsoft 365.

### 10.3 Προσωπικές ρυθμίσεις (όλοι)

Στη σελίδα **Notifications** κάθε άτομο επιλέγει κανάλια ανά γεγονός, **ώρες ησυχίας** (π.χ. 22:00–08:00, οι ειδοποιήσεις περιμένουν αντί να χαθούν), **σύνοψη** ανά ώρα ή ημέρα, ελάχιστη προτεραιότητα, και βλέπει τις συσκευές του με push. Εδώ βρίσκεται και η **υπογραφή** των agents.

**Σημαντικό:** τα push και email στέλνονται μέσω ουράς και ξαναδοκιμάζονται αυτόματα (2, 4, 8… λεπτά, έως 6 φορές). Για να δουλέψουν οι κανόνες, οι συνοψέις και οι επαναλήψεις χρειάζεται cron κάθε λεπτό (ενότητα 17).

## 11. Χρονοχρέωση, τιμή ανά ώρα και συμβόλαια

Ο χρόνος που καταγράφεται στα tickets γίνεται χρέωση: ώρες × τιμή ανά ώρα του organization, και αφαιρείται από το πακέτο ωρών του συμβολαίου.

### 11.1 Καταγραφή χρόνου (Agent)

- **Χρονόμετρο**: κάρτα **Time** στο ticket → **Start timer**. Συνεχίζει να μετράει ακόμη κι αν κλείσεις τη σελίδα. Με Stop συμπληρώνεται ο χρόνος· γράφεις σημείωση και πατάς **Log**.
- **Χειροκίνητα**: γράφεις τον χρόνο με όποιον τρόπο θέλεις: `45`, `1:30`, `1h 30m`, `1.5h`, `2 ώρες`. Επιλέγεις ημέρα και αν είναι **Billable**.
- **Με την απάντηση**: πεδίο **Time spent** δίπλα στο Send reply (καταγράφεται ως billable).
- Σβήνεις τις δικές σου καταχωρίσεις· των άλλων μόνο με το δικαίωμα Manage everyone’s time.

### 11.2 Τιμή ανά ώρα ανά organization

1. **Προεπιλογή workspace**: Reports → Time & billing → **Currency** (EUR, USD, GBP…) και **Default rate per hour**, π.χ. 40 €.
2. **Δική τιμή ανά πελάτη**: Settings → Organizations → το organization → **Hourly rate**, π.χ. 55,50 → **Save rate**. Άδειο = ισχύει η προεπιλογή του workspace.
3. Μετράει μόνο ο **billable** χρόνος. Ένα ticket χρεώνεται στο (πρώτο) organization του πελάτη που το άνοιξε.
4. Το ποσό φαίνεται: στην κάρτα Time του ticket, στο Reports → Time & billing και στο Excel χρεώσεων.

### 11.3 Συμβόλαια υποστήριξης

| Πεδίο | Τι κάνει |
| --- | --- |
| Name | Π.χ. «Gold 2027» |
| Starts / Ends | Διάρκεια· χωρίς λήξη = αορίστου |
| Hours included | Πακέτο ωρών· άδειο = απεριόριστη υποστήριξη |
| Reply within (h) | Εμφανίζεται στο ticket ως στόχος πρώτης απάντησης |
| Solve within (h) | Ορίζει την προθεσμία των νέων tickets, αντί για το SLA του workspace |
| Active | Ανενεργό συμβόλαιο δεν μετράει |

Το ticket δείχνει το υπόλοιπο με χρώμα: πράσινο εντάξει, πορτοκαλί όταν μένει κάτω από 15% ή λιγότερο από 14 ημέρες, κόκκινο όταν ξεπεραστεί ή λήξει. Αν το organization είχε συμβόλαια αλλά κανένα ενεργό, εμφανίζεται «No active support contract».

### 11.4 Παράδειγμα μήνα

Η «Αλφα Λογιστική» έχει τιμή 55,50 €/ώρα και συμβόλαιο 10 ωρών. Τον Νοέμβριο ο agent καταγράφει:

| Ημέρα | Ticket | Χρόνος | Billable |
| --- | --- | --- | --- |
| 03/11 | #128 Εκτυπωτής | 1:30 | Ναι |
| 12/11 | #131 Νέος υπάλληλος | 0:45 | Ναι |
| 12/11 | #131 εσωτερικός έλεγχος | 0:20 | Όχι |

Αποτέλεσμα στο Reports → Time & billing: 2h 15m billable × 55,50 € = **124,88 €**, 20m μη χρεώσιμα, και στο συμβόλαιο «7h 45m left of 10h». Το **Excel** έχει δύο φύλλα: σύνολα ανά organization και κάθε καταχώριση με ποσό — έτοιμο για τιμολόγηση.

Το **Reports** (δικαίωμα View reports) δείχνει όγκο, χρόνους, SLA και ικανοποίηση για 7, 30, 90 ημέρες ή 12 μήνες.

- **Excel χρεώσεων** (κάρτα Time & billing): σύνολα ανά organization και όλες οι καταχωρίσεις του μήνα με ποσό.

### 12.2 Προγραμματισμένα emails

Κάρτα **Scheduled emails** (δικαίωμα Schedule report emails):

1. **New schedule** → όνομα, συχνότητα (κάθε μέρα, εβδομάδα ή μήνα), ώρα, περίοδος.
2. **Organization**: «All organizations» ή μία συγκεκριμένη (μετράνε μόνο τα tickets των ανθρώπων της).
3. **Recipients**: χρήστες με δικαίωμα αναφορών, και **Other email addresses** για οποιονδήποτε άλλο.

**Παράδειγμα:** «Μηνιαία αναφορά Αλφα», κάθε μήνα στις 08:00, τελευταίες 30 ημέρες, Organization = Αλφα Λογιστική, παραλήπτης it@alfa-logistiki.gr. Ο πελάτης παίρνει κάθε μήνα τα δικά του νούμερα. **Preview** δείχνει το email, **Send now** το στέλνει αμέσως.

## 13. AI βοηθός (Claude)

Ο AI βοηθός γράφει και βελτιώνει κείμενα για τους agents· τίποτα δεν στέλνεται στον πελάτη χωρίς έλεγχο από άνθρωπο.

### 13.1 Ενεργοποίηση (Admin)

1. Δημιουργείς API key στο console.anthropic.com → API keys (ξεκινά με sk-ant-).
2. Settings → Integrations → **AI assistant (Claude)**: Turn on, επικολλάς το κλειδί (αποθηκεύεται κρυπτογραφημένο), διαλέγεις μοντέλο.
3. **Test connection** για έλεγχο.
4. Στους ρόλους που θα το χρησιμοποιούν δίνεις το δικαίωμα **AI assistant**.

| Μοντέλο | Πότε |
| --- | --- |
| Claude Opus 5.5 (προεπιλογή) | Καλύτερη ποιότητα |
| Claude Sonnet 5.5 | Γρήγορο και ικανό |
| Claude Haiku 5.5 | Ταχύτατο, χαμηλότερο κόστος |

### 13.2 Το μενού AI στην απάντηση (Agent)

- **Suggest a reply**: διαβάζει όλη τη συνομιλία και γράφει πρόταση απάντησης στη γλώσσα του πελάτη. Αν έχεις ξεκινήσει κείμενο, το χρησιμοποιεί ως βάση. Δεν εφευρίσκει τιμές ή ημερομηνίες· βάζει \[συμπλήρωσε\].
- **Summarize the ticket**: σύνοψη σε κουκίδες (πρόβλημα, τι έγινε, τι μένει). Με **Copy** ή **Use as internal note** την κρατάς.
- **Improve my text**: More professional, Friendlier, More empathetic, Shorter, Fix spelling & grammar.
- **Translate my text to**: English, Ελληνικά, Deutsch, Français ή Other language…
- Κάθε αλλαγή έχει **Undo**.

**Παράδειγμα:** γράφεις «δεν είναι δικό μας πρόβλημα, μιλήστε με τον πάροχο» → **More empathetic** → «Καταλαβαίνουμε την ταλαιπωρία. Από τον έλεγχο μας φαίνεται ότι το θέμα βρίσκεται στη σύνδεση…».

### 13.3 Αυτόματη ταξινόμηση νέων tickets

- Επιλογή **Triage new tickets automatically**: για κάθε νέο ticket εντοπίζει τη διάθεση του πελάτη. Θυμωμένοι ή ενοχλημένοι πελάτες παίρνουν ένδειξη **Angry** / **Frustrated** (μόνο το προσωπικό τη βλέπει).
- **Also set category and priority**: βάζει κατηγορία (μόνο αν ο πελάτης δεν έβαλε) και priority. Η αιτιολογία γράφεται στο History, π.χ. «AI triage: set category Technical, priority Urgent · mood angry — δεν λειτουργεί το ταμείο σε κανένα κατάστημα».
- Ισχύει μόνο για tickets που ανοίγουν μετά την ενεργοποίηση.

### 13.4 Άρθρο από ticket

Κουμπί **Article from ticket** (δικαίωμα Write & edit articles): από ένα λυμένο ticket γράφει πρόχειρο άρθρο Help Center με βήματα, χωρίς ονόματα και στοιχεία του πελάτη, και σε πηγαίνει στην επεξεργασία. Δημοσιεύεται μόνο όταν το εγκρίνεις.

### 13.5 Ασφάλεια και κόστος

- Το κείμενο του ticket στέλνεται στο API της Anthropic μόνο όταν κάποιος πατήσει κάτι από το μενού (ή για την ταξινόμηση, αν είναι ενεργή). Οι εσωτερικές σημειώσεις στέλνονται μόνο αν ο agent έχει δικαίωμα να τις βλέπει.
- Όριο: 30 αιτήματα ανά άτομο ανά 10 λεπτά. Το κόστος χρεώνεται στον λογαριασμό Anthropic του κλειδιού.
- Στο Windows, αν εμφανιστεί σφάλμα πιστοποιητικού SSL, ορίζεις `curl.cainfo` στο php.ini.

## 14. Help Center, έτοιμες απαντήσεις και αυτοματισμοί

Οι πελάτες λύνουν μόνοι τους συχνά θέματα από το Help Center, και οι agents απαντούν ταχύτερα με έτοιμα κείμενα και κανόνες.

### 14.1 Help Center (Knowledge base)

- **Knowledge base → New article**: τίτλος, ενότητα (π.χ. «Account»), κείμενο με εικόνες. Μένει draft μέχρι να το δημοσιεύσει κάποιος με δικαίωμα Publish.
- Οι πελάτες βλέπουν μόνο δημοσιευμένα άρθρα, με κουμπί «Χρήσιμο;». Οι editors βλέπουν προβολές και βαθμολογία.
- Τα άρθρα προτείνονται αυτόματα όταν κάποιος γράφει νέο αίτημα, και ο agent βάζει link με το βιβλίο του editor.
- Νέα άρθρα γρήγορα: **Article from ticket** με AI (ενότητα 13.4).

### 14.2 Canned replies και μεταβλητές

Settings → Tags & replies → **Canned responses**. Οι μεταβλητές γέμιζουν με τα στοιχεία του ticket (ισχύουν και στα macros):

| Μεταβλητή | Παράδειγμα |
| --- | --- |
| {customer.name} / {customer.first\_name} | Γιάννης Παπαδόπουλος / Γιάννης |
| {customer.email} | giannis@acme.gr |
| {organization.name} | Acme ΑΕ |
| {ticket.number} / {ticket.subject} / {ticket.status} | #128 / Δεν τυπώνει / Open |
| {ticket.link} | https://support.softify.gr/tickets/… |
| {agent.name} / {agent.first\_name} / {agent.email} | Μαρία Κωνσταντίνου / Μαρία / … |
| {workspace.name} / {today} | Softify / 11 Nov 2026 |

Παράδειγμα canned: «Γεια σας {customer.first\_name}, λάβαμε το αίτημα {ticket.number} και το εξετάζουμε. — {agent.first\_name}, {workspace.name}».

### 14.3 Macros και templates

- **Macro** = απάντηση ή σημείωση + αλλαγή status και/ή assignee με ένα κλικ. Παράδειγμα: «Ζητώ στοιχεία» → στέλνει «Στείλτε μας στιγμιότυπο του μηνύματος…» και βάζει status Pending.
- **Ticket template** = έτοιμο νέο ticket (θέμα, περιγραφή, κατηγορία, priority) που εμφανίζεται στο «Start from a template».

### 14.4 Αυτοματισμοί

Settings → **Automations**: κανόνες που τρέχουν σε κάθε νέο ticket, με τη σειρά που εμφανίζονται.

- **Συνθήκη** (προαιρετική): priority ή κατηγορία.
- **Ενέργεια**: ανάθεση σε agent, αλλαγή priority, αλλαγή status ή tag.

Παράδειγμα: «Αν κατηγορία = Billing → ανάθεση στη Σοφία». Αν χρειάζεσαι κατανομή σε ομάδα, χρησιμοποίησε καλύτερα τη δρομολόγηση κατηγορίας → group με αυτόματη ανάθεση (Settings → Groups).

## 15. Ενσωματώσεις

Το TicketingOS μιλάει με άλλα συστήματα με δύο τρόπους: REST API (εσείς ρωτάτε) και webhooks (αυτό σας ειδοποιεί). Ρύθμιση στο Settings → Integrations.

### 15.1 REST API

Με **API keys → Create** παίρνεις κλειδί `tos_…` (φαίνεται μία φορά). Κάθε κλήση στέλνει `Authorization: Bearer tos_…` και έχει τα δικαιώματα του χρήστη που έφτιαξε το κλειδί.

| Κλήση | Τι κάνει |
| --- | --- |
| GET /api/v1/me | Ποιος είμαι |
| GET /api/v1/tickets | Λίστα tickets με φίλτρα |
| POST /api/v1/tickets | Νέο ticket |
| GET / PATCH /api/v1/tickets/{id} | Στοιχεία / αλλαγή status, priority, assignee |
| GET / POST /api/v1/tickets/{id}/comments | Μηνύματα / νέα απάντηση ή σημείωση |
| GET /api/v1/users, /organizations, /groups, /fields, /meta | Βοηθητικά στοιχεία |

Παράδειγμα νέου ticket από το ERP:

```bash
curl -X POST https://support.softify.gr/api/v1/tickets \
  -H "Authorization: Bearer tos_xxxxxxxx_…" \
  -H "Content-Type: application/json" \
  -d '{"subject":"Σφάλμα συγχρονισμού αποθήκης","description":"Η εργασία των 02:00 απέτυχε","requester":{"email":"it@acme.gr"},"priority":"HIGH"}'
```

### 15.2 Webhooks: Slack, Teams, Viber, JSON

| Μορφή | Τι στέλνει | Τι χρειάζεσαι |
| --- | --- | --- |
| Slack | Μήνυμα σε κανάλι | Incoming webhook URL |
| Microsoft Teams | Κάρτα με προτεραιότητα, status, πελάτη και κουμπί «Open ticket» | URL από Teams Workflows («When a Teams webhook request is received») |
| Viber channel | Μήνυμα στο κανάλι | Token: κανάλι Viber → Settings → Developer tools |
| JSON (signed) | Πλήρη δεδομένα με υπογραφή HMAC | Δικό σας endpoint |

- Γεγονότα: ticket created, updated, closed, comment created, CSAT received.
- **Only high and urgent tickets**: στέλνει μόνο τα tickets με τις δύο υψηλότερες προτεραιότητες — ιδανικό για κανάλι «Επείγοντα» στο Teams ή στο Viber.
- **Send test** δοκιμάζει τη σύνδεση· οι τελευταίες αποστολές φαίνονται με το αποτέλεσμα. Αποτυχίες ξαναδοκιμάζονται έως 6 φορές· μετά από 25 αποτυχίες το webhook σταματά.

**Παράδειγμα Teams:** στο Teams, κανάλι «Υποστήριξη» → ⋯ → Workflows → «Post to a channel when a webhook request is received» → αντιγράφεις το URL. Στο TicketingOS: νέο webhook, Μορφή Microsoft Teams, γεγονός Ticket created, τικ «Only high and urgent tickets» → Add webhook → Send test.

## 16. Αντίγραφα, GDPR και ασφάλεια

Από το Settings → **Backups & data** κρατάς αντίγραφα, δίνεις δεδομένα σε πελάτες και εκτελείς αιτήματα διαγραφής. Κάθε ενέργεια γράφεται στο audit log.

### 16.1 Αντίγραφα ασφαλείας

- **Download backup**: ZIP με όλα τα δεδομένα του workspace (ένα JSON ανά πίνακα). **With files**: και τα αρχεία των tickets.
- **Ημερήσιο αντίγραφο**: τικ «Make a backup every day», πόσες ημέρες κρατιούνται (π.χ. 7) και αν περιλαμβάνουν αρχεία. Ο φάκελος storage/backups δεν είναι προσβάσιμος από το web.
- Σε κανένα αντίγραφο δεν μπαίνουν κωδικοί, tokens ή κλειδιά API.
- Συμβουλή: κατέβαζε τακτικά ένα αντίγραφο και κράτα το εκτός server. Το Plesk κάνει επίσης δικά του αντίγραφα (Backup Manager) της βάσης και των αρχείων.

### 16.2 Εξαγωγή organization

Επιλέγεις organization → **Download ZIP**: people.csv, tickets.csv, messages.csv (και εσωτερικές σημειώσεις), time.csv, contracts.csv, προαιρετικά και αρχεία. Χρήσιμο όταν ένας πελάτης φεύγει ή ζητά το ιστορικό του.

### 16.3 GDPR

| Αίτημα | Τι κάνεις | Αποτέλεσμα |
| --- | --- | --- |
| «Θέλω τα δεδομένα μου» | Give a person their data → email → Download (JSON) | Προφίλ, organizations, tickets με δημόσια μηνύματα, βαθμολογίες |
| «Διαγράψτε με» | Erase a person → email δύο φορές → Erase | Όνομα και email αντικαθίστανται, ο λογαριασμός απενεργοποιείται, βγαίνει από organizations, συσκευές και ειδοποιήσεις. Τα tickets μένουν για το αρχείο σας |
| «Διαγράψτε και όσα έγραψα» | Όπως πάνω + «Also remove their messages… and files» | Και τα μηνύματα, οι περιγραφές και τα αρχεία του διαγράφονται |

Η διαγραφή δεν αναιρείται. Δεν μπορείς να διαγράψεις τον εαυτό σου, και έναν Admin τον διαγράφει μόνο όποιος έχει Manage administrators.

### 16.4 Ασφάλεια συνοπτικά

- Κωδικοί με hash, κλειδιά SMTP/AI κρυπτογραφημένα, προστασία CSRF σε κάθε φόρμα.
- Τα αρχεία αποθηκεύονται εκτός web και δίνονται μόνο σε όσους βλέπουν το ticket. Ο τύπος αρχείου ελέγχεται από την κατάληξη.
- Όρια συχνότητας σε σύνδεση, φόρμα και chat.
- **Audit log** με φίλτρα και εξαγωγή CSV.

## 17. Εγκατάσταση και συντήρηση (Plesk)

Η εφαρμογή είναι PHP 8.3 με MySQL/MariaDB, χωρίς έξτρα πακέτα. Η ενημέρωση γίνεται με Pull από το GitHub.

### 17.1 Απαιτήσεις

- PHP 8.3 με επεκτάσεις: pdo\_mysql, openssl, mbstring, curl, **zip** (αντίγραφα, Excel, ZIP αρχείων), gd.
- MySQL 8 ή MariaDB 10.6+.
- Document root: ο φάκελος **public** (π.χ. httpdocs/public).

### 17.2 Αρχική εγκατάσταση

1. Plesk → Git: σύνδεση με το repository, deploy στο httpdocs.
2. Δημιουργία βάσης και εισαγωγή του database/mysql-schema.sql (phpMyAdmin).
3. Αρχείο **.env** στο httpdocs: DB\_DRIVER=mysql, DB\_HOST, DB\_NAME, DB\_USER, DB\_PASS, APP\_URL=https://support.softify.gr, AUTH\_SECRET, VAPID κλειδιά, CRON\_KEY. Το .env δεν μπαίνει ποτέ στο GitHub.
4. Super Admin: `php bin/make-super-admin.php email` (ή με το SQL αρχικοποίησης).

### 17.3 Cron (απαραίτητο)

Plesk → Scheduled Tasks → Add task → *Run a PHP script* → `httpdocs/bin/cron.php`, ορίσματα `--log`, κάθε λεπτό (`* * * * *`). Κάθε εκτέλεση:

- στέλνει ειδοποιήσεις που περιμένουν και ξαναδοκιμάζει αποτυχίες, συνοψέις και αναφορές
- ελέγχει SLA, ανατέθητα, υπενθυμίσεις και αυτόματο κλείσιμο
- κάνει τα αναπάντητα chats tickets, την ταξινόμηση AI και το ημερήσιο αντίγραφο

Χωρίς cron στο server: GET /cron?key=το-CRON\_KEY από οποιοδήποτε εξωτερικό scheduler. Το Settings → Notifications δείχνει πότε έτρεξε τελευταία φορά και έχει κουμπί **Run now**.

### 17.4 Email

Settings → Notifications & email → κάρτα **Email notifications** (στο τέλος της σελίδας): SMTP (host, port, user, κωδικός, αποστολέας) ή Microsoft 365. **Send test email** για έλεγχο.

### 17.5 Ενημερώσεις

1. Plesk → Git → **Pull Updates**.
2. Οι αλλαγές στη βάση γίνονται αυτόματα με το πρώτο άνοιγμα της εφαρμογής — δεν χρειάζεται σκριπτ.
3. Οι χρήστες της εφαρμογής κινητού παίρνουν τη νέα έκδοση με το επόμενο άνοιγμα.
4. Νέα δικαιώματα ενεργοποιούνται αυτόματα στους Admin· στον ρόλο Agent ελέγξτε τα Roles & permissions.

### 17.6 Μέγεθος αρχείων

Το μέγιστο μέγεθος upload το ορίζει και η PHP. Για αρχεία πάνω από 8 MB: Plesk → PHP Settings → upload\_max\_filesize και post\_max\_size (π.χ. 32M).

## 18. Συχνές ερωτήσεις και προβλήματα

| Πρόβλημα | Λύση |
